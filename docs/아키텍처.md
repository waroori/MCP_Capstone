# 아키텍처 설계 v3.1 — 현재 구조

2026-10-22 · 작성 백엔드+DB · v3(10-21)에서 **지금 동작하는 것만** 남겼다. 아직 없는 것(대기열·Mock 벤더·compose 전체 배포 등)은 `docs/추후개발.md`.
그림: `docs/architecture.drawio` (1 시스템 구성도 · 2 배포 · 3 큐 처리·재시도[추후]). draw.io에서 파일 → 열기.

기능·시나리오는 `docs/설계문서.md` v2를 그대로 따른다. 이 문서는 **구조·프레임워크·API·장애 관리·배포**만 다룬다.

## 1. 목표와 원칙

| 목표 | 확인 방법 |
| --- | --- |
| 기능을 우리가 직접 점검할 수 있다 | `uv run pytest` + 시연 스크립트 |
| API가 계약으로 고정된다 | `packages/schemas` → `specs/*.json`, 계약 테스트 |
| 데이터가 안 깨진다 | DB 제약(UNIQUE·조건부 UPDATE), 승인 직전 재확인 (6절) |

원칙은 강의 레퍼런스(표 5-1)를 우리 스택에 맞춘 것이다.

1. 업무 규칙과 데이터 변경은 **backend 한 곳**. MCP·에이전트·Slack 봇은 DB에 직접 쓰지 않는다(에이전트 checkpointer·작업 이력 제외).
2. LLM 요청은 **202 + SSE**. 화면은 에이전트 주소를 모른다 — backend `/ai/tasks`가 중계한다.
3. 밖에서 닿는 것은 **admin_web(→ backend `/api`) 하나**. 에이전트·MCP·DB는 로컬/내부망에만.

## 2. 레퍼런스와 우리 구조 대응

| 레퍼런스 (강의) | 우리 | 상태 |
| --- | --- | --- |
| Vue 3 | admin_web (Vite) | 동작. `/api/*` 전부 backend로 (Vite 프록시, 운영은 nginx) |
| Spring Boot | backend (FastAPI) | 동작. PostgreSQL `app` 스키마, JWT, `/ai/tasks` 중계 |
| FastAPI Agent | agent_runtime | 동작. checkpointer·작업 이력은 PostgreSQL `agent` 스키마 |
| business-mcp | mcp_work | 동작 (backend REST 호출) |
| rag-mcp | mcp_docs | 검색 도구 동작(SQLite FTS5, 메모리). 문서 원문 Resource는 **추후** |
| PostgreSQL 16 | postgres | 동작 (`docker-compose.yml`) |
| Vector DB | — | 선택, 추후 (pgvector) |
| — (가산점) | rabbitmq + worker + beat | **추후** (`docs/추후개발.md` 1절) |

> **의도된 차이**: 레퍼런스는 business-mcp가 `/internal/**`를 부르지만, 우리는 **요청자 JWT를 그대로 넘겨 공개 API를 부른다**. 권한 검사가 backend 한 곳에서 같은 규칙으로 일어나므로 규칙 복제가 없고, 내부 전용 경로를 따로 지킬 필요도 없다. `/internal/**`은 배치 트리거처럼 사람이 부르지 않는 경로에만 쓴다.

## 3. 프레임워크

| 계층 | 선택 | 고른 이유 / 대안 |
| --- | --- | --- |
| 화면 | Vue 3 + Vite 6 | 관리자 콘솔 하나. (구) Streamlit 화면은 삭제 |
| API 서버 | FastAPI + Uvicorn | Pydantic 스키마와 직결 |
| DB 접근 | **SQLAlchemy 2.0 Core** (`text()`로 SQL 직접) | 엔진·트랜잭션만 쓴다. ORM 모델을 두지 않아 스키마는 `db/schema.sql` 한 곳 |
| 스키마 관리 | `db/schema.sql` + `db/reset.sh` | 지우고 다시 만든다. 운영 데이터가 생기면 Alembic (추후) |
| DB | PostgreSQL 16 | 백엔드·체크포인터 동시 쓰기. SQLite는 잠금 충돌 |
| 인증 | PyJWT + bcrypt | Keycloak·OAuth는 일정에 과함 |
| 에이전트 | LangGraph + langgraph-checkpoint-postgres | 레퍼런스 그대로 |
| MCP | FastMCP (Streamable HTTP) | 레퍼런스 그대로 |
| HTTP 클라이언트 | httpx | 중계·MCP·에이전트 도구. slack_bot만 requests (추후 통일) |

## 5. API 설계

### 5-1. 공통 규약
- 성공 `{"data": …, "meta": {"request_id"}}`, 오류 `{"error": {"code", "message", "details"}}` — `apps/backend/errors.py`
- 오류 코드 ↔ HTTP 상태는 `schemas.common.HTTP_STATUS_BY_CODE` 하나에서 관리
- 모든 요청은 `Authorization: Bearer <JWT>`

### 5-2. 인증
| Method | Path | 설명 |
| --- | --- | --- |
| POST | `/auth/login` | 사번(또는 이메일)+비밀번호 → JWT (HS256, 1시간, claim: `sub`, `role`). 5회 실패 시 5분 잠금 |
| POST | `/auth/dev-login` | 개발용. `APP_ENV=prod`면 막힘 |
| POST | `/auth/slack-exchange` | 시스템 계정 전용. Slack 봇이 Slack 사용자 대신 직원 JWT를 받는다 (`SLACK_USER_MAP` → 없으면 직원의 `slack_user_id`) |
| GET | `/me` | 토큰 주인. MCP·에이전트가 역할 확인에 쓴다 |

시스템 계정(배치·Slack 워커·에이전트 검토)은 `SYSTEM_TOKEN`으로 부른다. `APP_ENV=prod`에서는 서명된 JWT여야 한다: `uv run python -m apps.backend.auth` (1년, 유출 시 `JWT_SECRET` 교체).
외부에 공개(Cloudflare 터널)할 때는 `APP_ENV=prod`로 띄운다. dev면 dev-login·`dev.<id>` 토큰으로 누구나 관리자가 될 수 있다.

### 5-3. AI 작업 중계 (레퍼런스 표 5-8)
| Method | Path | backend가 하는 일 |
| --- | --- | --- |
| POST | `/ai/tasks` | 로그인 확인 → agent `POST /ai/tasks` 전달 → 202 `{task_id}` |
| GET | `/ai/tasks?mine=` | 전달 |
| GET | `/ai/tasks/{id}` | 전달 |
| GET | `/ai/tasks/{id}/stream?after=` | agent SSE를 그대로 흘려보냄 (httpx 스트리밍) |
| POST | `/ai/tasks/{id}/approval` | 전달 → 202 |

- backend는 **로그인만** 확인하고 그대로 넘긴다. 역할 규칙(본인 작업만, 승인은 관리자)은 에이전트가 backend `/me`로 다시 확인한다.
- 요청·응답 모양은 `schemas/agent.py`(`specs/openapi.agent.json`) 그대로.
- 에이전트에 연결되지 않으면 `503 {"error":{"code":"agent_unavailable"}}`.
- Slack 봇은 내부에서 돌므로 에이전트(`AGENT_URL`)를 직접 부른다.

### 5-4. 업무 API
기존 라우트(`/plans`, `/inventory`, `/usage`, `/anomalies`, `/suggestions`, `/confirmations`, …)와 `response_model`은 계약 테스트로 고정한다. 목록은 `schemas.rest.ROUTES`.

### 5-5. 운영 API
| Method | Path | 역할 | 설명 |
| --- | --- | --- | --- |
| POST | `/internal/jobs/{name}/run` | admin, system | 배치를 **동기 실행**하고 `job_runs`에 기록 (큐 전환은 추후) |

## 6. 데이터

한 PostgreSQL 인스턴스, 스키마 둘.

| 스키마 | 소유 | 테이블 |
| --- | --- | --- |
| `app` | backend | 설계문서 6절 테이블 + `job_runs` |
| `agent` | agent_runtime | LangGraph checkpoint 테이블, 작업·이벤트 이력 (에이전트가 기동 때 만든다) |

무결성은 DB 제약으로 막는다.
- `seat_assignments (contract_id, employee_id)` 배정 중(`status='assigned'`) UNIQUE → 다시 실행해도 이중 배정 없음
- `action_plans` 상태 전이는 현재 상태를 조건으로 건 `UPDATE … WHERE status = …` 로 (실행 직전 재확인)
- `job_runs.idempotency_key` UNIQUE

## 7. 장애 관리

| 장애 | 감지 | 처리 | 사용자가 보는 것 |
| --- | --- | --- | --- |
| LLM 429·503 | Harness Recovery | 2회 재시도 → 대체 모델 → FAILED | "다시 시도 중" 이벤트, 최종 FAILED |
| 에이전트 다운 | backend 중계 연결 실패 | 503 `agent_unavailable` | "AI 비서 서버가 응답하지 않습니다" |
| MCP 다운 | 에이전트 도구 호출 실패 | ToolMessage로 모델에 전달 | 답변에 "조회 실패" 명시 |
| 같은 요청 두 번 | UNIQUE·조건부 UPDATE | 두 번째는 충돌(409) 또는 첫 결과 | 변화 없음 |
| DB 연결 끊김 | `pool_pre_ping` | 재연결, 실패 시 500 JSON | 오류 메시지 |
| 승인 대기 중 서버 재시작 | checkpointer(Postgres) | 같은 thread로 재개 | 승인 카드 유지 |

컨테이너 자동 재시작·큐 재시도·DLQ는 `docs/추후개발.md`.

## 8. 실행 · 배포

- 로컬: `docker compose up -d postgres` + `scripts/run_all.sh` (backend·MCP 2개·agent·Vite). 명령 모음은 `docs/로컬실행.md`.
- 외부 공개: Cloudflare. 브라우저 → Cloudflare(고정 주소) → Tunnel → 로컬 Vite(:5173) → `/api/*`는 backend. 에이전트·MCP·DB는 터널 밖으로 나가지 않는다.
- 비밀값은 `.env`로만 (`.env.example` 참고).
