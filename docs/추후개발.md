# 추후 개발 사항

2026-10-22 · `docs/아키텍처.md` v3에서 분리. 지금 동작하는 구조는 아키텍처 문서, **아직 없는 것**은 이 문서에 둔다.
하나를 끝내면 해당 절을 아키텍처 문서로 옮기고 여기서 지운다.

## 1. 비동기 대기열 (RabbitMQ + Celery, 가산점)

**지금**: `POST /internal/jobs/{name}/run`이 요청 안에서 **동기로** 실행하고 `job_runs`에 `done` 1건을 남긴다. 재시도·DLQ는 없다.
수집 배치(`collect_usage`, `collect_release_notes`)는 mock_vendor가 없어 `{"stub": true}`를 돌려준다.

| 큐 | 작업 | 누가 넣나 | 재시도 |
| --- | --- | --- | --- |
| `batch` | collect_usage → check_thresholds, collect_release_notes | beat, `/internal/jobs/*/run` | 3회, 10s·30s·90s |
| `agent` | run_system_agent (review_update, review_seat_request) | batch 작업 결과 | 3회. 에이전트 FAILED·503이면 재시도 |
| `notify` | send_suggestion (Slack), confirmation 기한 알림 | 알림 정책 통과 시 | 3회. 업무 시간 밖이면 `eta`로 다음 09:00 예약 |
| `batch` | execute_plan (Mock 벤더 좌석 실행) | 승인된 plan | 3회. `Idempotency-Key`로 중복 실행 없음 |

규칙
- 재시도는 **일시 오류만**(연결 실패, 5xx, 429, 타임아웃). 4xx·검증 실패는 바로 `failed`.
- 3회 실패하면 DLQ(`jobs.dlq`) + `job_runs.status=dead`, 관리자 화면에서 수동 재실행. 흐름은 `docs/architecture.drawio` 3페이지.
- worker·beat는 backend와 **같은 코드**를 다른 명령으로 띄운다(`celery -A apps.backend.jobs worker|beat`).
- APScheduler(설계문서 5·10절, `jobs/README.md`)는 Celery beat로 대체한다.

할 일
- 의존성 `celery` 추가, `apps/backend/jobs/` (Celery 앱 + 태스크)
- `/internal/jobs/{name}/run` → 큐에 넣고 202 `{job_id}`
- 운영 API: `GET /internal/jobs?status=dead`(admin), `POST /internal/jobs/{id}/retry`(admin)
- 관리자 화면 '실패 작업' 목록

## 2. Mock 벤더 + 장애 주입

- `apps/mock_vendor/main.py` (포트 8001): OpenAI·Anthropic·xAI·Adobe Mock API, `?fail_rate=` 로 503 주입
- `apps/backend/adapters/`: `VendorAdapter` Protocol + mock 구현(httpx). 수집 배치의 stub을 이걸로 바꾼다
- 시연: `fail_rate=0.5`로 재시도 → 성공, `fail_rate=1.0`으로 DLQ까지

## 3. 운영 · 배포 (docker compose 전체)

지금 compose에는 postgres만 있고 나머지는 `scripts/run_all.sh`로 띄운다.

| 서비스 | 이미지·명령 | 포트 | 공개 | depends_on (healthy) |
| --- | --- | --- | --- | --- |
| postgres | `postgres:16-alpine` (벡터 검색을 하면 `pgvector/pgvector:pg16`) | 5432 | – | – |
| rabbitmq | `rabbitmq:3.13-management` | 5672 / 15672 | 15672는 127.0.0.1만 | – |
| mock_vendor | app 이미지 `uvicorn apps.mock_vendor.main:app` | 8001 | – | – |
| backend | `uvicorn apps.backend.main:app` | 8000 | ○ | postgres, rabbitmq |
| mcp_work · mcp_docs | `python -m apps.mcp_work.server` 등 | 8010 · 8011 | – | backend |
| agent | `uvicorn apps.agent_runtime.main:app` | 8002 | – | mcp_work, mcp_docs, postgres |
| worker | `celery -A apps.backend.jobs worker -Q batch,agent,notify` | – | – | backend, rabbitmq |
| beat | `celery -A apps.backend.jobs beat` | – | – | rabbitmq |
| admin_web | `apps/admin_web/Dockerfile` (nginx) | 80 | ○ | backend |
| slack_bot | `python -m apps.slack_bot` (profile `slack`) | – | – | backend |

할 일
- Python 서비스 공용 `docker/Dockerfile` (python:3.12-slim + `uv sync --frozen`), 서비스마다 `command`만 다르게
- backend `GET /healthz` (DB·RabbitMQ 연결 확인), compose `healthcheck` + `restart: unless-stopped`
- 서비스 주소는 compose 이름(`http://backend:8000`), 비밀값은 `.env`로만

## 4. MCP 문서 서버

- **문서 원문 Resource 1개** (강의 3절 필수) — `apps/mcp_docs/server.py`. 지금은 검색 도구만 있다
- (선택) 벡터 검색: SQLite FTS5 → pgvector

## 5. 코드 정리 (급하지 않음)

- `apps/backend/main.py`(1100줄+)를 `routers/`(me, catalog, f1~f4, plans, audit, ai, jobs)·`services/`(알림 정책, 승인 상태머신, 좌석 배정)로 분리
- 마이그레이션 도구(Alembic): 지금은 `db/schema.sql` + `db/reset.sh`(지우고 다시 만듦). 지우면 안 되는 운영 데이터가 생길 때 도입
- `X-Trace-Id` 전 서비스 전달 (backend 중계는 이미 넘긴다), `job_runs`·LangSmith에 같은 id
- slack_bot의 `requests` → `httpx` (다른 서비스와 통일하고 의존성 하나 줄이기)

## 6. 점검 체크리스트 (위 항목이 생기면)

| 항목 | 명령 / 방법 | 기대 결과 |
| --- | --- | --- |
| 기동 | `docker compose up -d && docker compose ps` | 전 서비스 `healthy` |
| 큐 재시도 | `fail_rate=0.5`로 `collect_usage` 실행 | `job_runs.attempt` 증가 후 done |
| DLQ | `fail_rate=1.0` | `dead` 1건, 수동 재실행 후 done |
| 자가 복구 | `docker compose kill agent` | 중계 503 → 재시작 후 정상 |
